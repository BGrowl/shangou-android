# 安装与使用

## 运行条件

当前实际验证的是Android 10、1080×2340设备上的AutoX.js v7。源码保留其他Auto.js兼容写法，但尚无完整兼容验证。源码含E4X界面语法，不能直接用Node执行。

活动账号需先在官方手机App完成正常登录及活动所需认证。程序不管理账号凭据，不读取Cookie。活动资格与库存由平台决定。

## 放置文件

建议把以下两个文件放到 `/sdcard/shangou/`：

```text
/sdcard/shangou/
  shangou.js
  config.json       从仓库config.example.json复制并校准
```

在AutoX中打开 `shangou.js`，按运行按钮。首次确认无障碍服务可用。运行目录 `DIR` 会尝试从脚本来源解析，失败时回退到 `/sdcard/shangou`；不要仅从主文件所在位置推断配置目录。统一上述目录可以避免旧工程出现的“主文件在脚本目录、配置实际在另一个目录”的混淆。

历史部署还保留 `/sdcard/脚本/shangou.js` 镜像入口，这是旧工程的路径，不是新安装必须准备的第二份。不要同时运行两个版本。

## 首次校准

1. 在手机官方App打开目标活动页，确认对应活动和券，不要使用电脑网页代替手机页面。
2. 对照当前分辨率检查入口坐标、券按钮坐标、目标区域与页面锚点。样例配置仅适合历史布局。
3. 使用控制页“一键标定”，按实际节点确认目标。节点存在不代表该节点就是正确场次或正确券。
4. 回到目标活动页，确认无障碍可读到相关页面文字。首次接入应先做页面检查，避免直接调用领取演练。
5. 启动守候后，独立执行器接管调度。自动启动可能关闭控制页，这是预期行为。

“立即测试一次”会进行实际触控流程，不是离线仿真。不要为了检查安装状态而随意使用它。开发机 `npm test` 才是完全离线检查。

## 常驻与停止

控制页可以关闭，电脑可以断开；执行器仍需AutoX脚本服务、无障碍、网络和手机正常运行。不要把“可关闭控制界面”理解为“可以强制停止AutoX”。如果手机有安全锁屏，脚本的唤醒与滑动不能保证解锁。

需要停止时重新打开主脚本控制页并点击“停止”。它会终止本项目的独立执行器，删除自动启动标记与心跳；不会故意停止其他脚本。

`autostart.flag` 使主脚本再次被拉起时恢复守候，**本项目没有自动配置系统开机启动或外部定时任务**。手机重启或AutoX服务被终止后，需要由用户或另行配置的机制重新启动主脚本。

## 生成文件

| 路径（相对DIR） | 用途 |
|---|---|
| `config.json` | 本机配置 |
| `shangou-daemon.js` | 自动生成的独立执行器 |
| `daemon.heartbeat` | 守候循环心跳，不等于领取成功 |
| `autostart.flag` | 主脚本再次运行时自动恢复的标记 |
| `entry-status.json` | 最近一次进场失败证据 |
| `result.json` | 最新一场的结果 |
| `results/*.json` | 按场次、目标日期和归档时间保存的结果 |
| `logs/YYYY-MM-DD.log` | 日志，可能先缓存在内存中 |

核对某一场时读取该场独立结果；晚间的 `result.json` 很可能已经被后续场次覆盖。

## 升级

先停止独立执行器，备份主文件与本机配置，再替换源码。确认只有一个 `shangou-daemon.js` 引擎、构建号正确、活动页正常、心跳连续更新。旧执行器已在内存中加载旧核心，不能只覆盖磁盘文件便宣布升级完成。

验证升级时不需要点击领取。当前脚本状态与业务结果应分别核验，详细方法见[开发说明](DEVELOPMENT.md)。
